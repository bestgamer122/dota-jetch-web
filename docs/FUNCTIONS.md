# Cloud Functions

Серверная часть решает две задачи, которые нельзя закрыть в браузере.

## 1. Честный рейтинг мини-игр

Сейчас `mmr` и `score` считает клиент и пишет прямо в базу. Пользователь может отправить
любое число в допустимом диапазоне. Правила Firebase такое не ловят — они не знают,
какой результат «настоящий».

Функция `submitScore`:

- проверяет игру и результат (`functions/src/scoring.js`);
- считает MMR **сама**, по той же формуле, что и клиент;
- обновляет `users/<uid>` транзакцией;
- ограничивает частоту отправок (20 в минуту);
- обновляет `leaderboards` и `publicProfiles` только из проверенных данных.

Правила базы после внедрения: `users/<uid>/minigames_*` и `leaderboards/*` доступны только
админ-UID и сервисному аккаунту. Клиенту — запрещено (кроме чтения своего профиля).

## 2. Токены API вне браузера

`js/profile-analyzer.js` содержит STRATZ-токен в открытом виде — любой может его достать.
Функции `opendota` и `stratz` проксируют запросы, токены берутся из конфигурации:

```bash
firebase functions:config:set opendota.key="..." stratz.token="..."
```

Клиент после перехода обращается к `/opendota?path=matches/123` и `/stratz` вместо
прямых запросов, а токен из `profile-analyzer.js` удалён.

### Что сделать после деплоя

В [js/profile-analyzer.js](../js/profile-analyzer.js) заполнить адрес функции:

```js
STRATZ_PROXY: "https://europe-west1-<project-id>.cloudfunctions.net/stratz",
```

Пока поле пустое, вкладка «Мой профиль» показывает понятную ошибку
«Профиль временно недоступен: не настроен серверный прокси STRATZ», а не падает.

## Развёртывание

```bash
cd functions
npm install
firebase deploy --only functions
```

Требуется Firebase Blaze (Cloud Functions недоступны на бесплатном Spark).

## Проверка без развёртывания

Чистая логика вынесена в `functions/src/scoring.js` и покрыта тестами:

```bash
npm test
```

Тесты запускаются без `npm install` — модуль не имеет зависимостей.
