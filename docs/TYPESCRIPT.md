# План перехода на TypeScript

## Почему не «просто переписать»

Проект — статические скрипты: файлы грузятся тегами `<script>`, всё общается через глобальные
имена (`Store`, `UI`, `el`, `PAGES`). TypeScript в таком виде не работает без сборки:
браузер не умеет запускать `.ts`.

Полноценный `.ts` требует шага сборки (Vite/esbuild) — меняется процесс публикации.
Поэтому переход идёт этапами, и первые этапы не требуют сборки вообще.

## Этап 1. Подсказки типов без сборки

Уже готово:

- `tsconfig.json` — `allowJs`, `checkJs: false`, `noEmit`;
- `types/globals.d.ts` — описания `Store`, `CloudSync`, `MatchEntry`, `DiaryNote`, `Hero`.

Редактор (VS Code / WebStorm) подхватывает это автоматически: появляются подсказки
и подсветка несуществующих полей вроде `data.slug`.

Проверка глазами и через `tsc`:

```bash
npm install       # нужен интернет
npm run typecheck
```

## Этап 2. Включение проверки по файлам

`checkJs` включается постепенно — по одному файлу, начиная с самых «чистых»:

1. `js/config.js`, `js/sync.js` — данные, почти нет DOM;
2. `js/rating.js`, `js/daily.js`, `js/achievements.js` — арифметика и правила;
3. `js/history.js`, `js/diary.js`;
4. `js/auth.js`, `js/admin-panel.js`;
5. рендереры страниц (`games.js`, `profile-analyzer.js`, `app.js`).

Проверить текущий остаток в строгом режиме:

```bash
npm run typecheck:strict
```

Состояние на момент внедрения: **103 ошибки** (было 434, часть устранена).
Почти все — `TS2339`: значение из Firebase-снимка приходит как `unknown`
и требует явного сужения (`/** @type {Record<string, any>} */ (snap.val())`).
Это работа по файлам, а не блокер.

Обычный `npm run typecheck` (`checkJs: false`) проходит без ошибок и
проверяет только декларации — он годится для CI, пока идёт переход.

Файлы `js/brain*.js`, `js/assistant.js`, `js/external-ai.js`,
`js/hero-codex.js`, `js/web-search.js` исключены из проверки: они не
подключены в `index.html` и содержат ссылки на несуществующие глобалы
(`findHeroByAlias`, `HEROES_DB`, `ITEM_NOTES`). Подключать их в текущем
виде нельзя.

## Этап 3. Сборка и настоящий `.ts`

Вводится, когда понадобится минификация и разделение на модули:

- Vite или esbuild, точка входа — `js/app.js`;
- глобальные `var` превращаются в `import`/`export`;
- `?v=` в `index.html` заменяется хэшами файлов;
- порядок загрузки перестаёт иметь значение.

После этого файлы переименовываются в `.ts` без изменения логики.

## Что даёт на практике

Реальные ошибки из истории проекта, которые ловятся типами:

| Ошибка | Как ловится |
|---|---|
| `data.mmr.toLocaleString()` на строке из Firebase | `mmr: number` вместо `any` |
| история без `slug` → картинки не грузятся | обязательное поле в `MatchEntry` |
| `Store.get("guessbeststreak")` вместо `guessBest` | union-тип ключей хранилища |
| вызов удалённой `stopAutoSave()` | `Cannot find name` |
| `players[0]` — не тот игрок | отдельный тип для состава матча |

Чего типы **не** ловят: логические циклы (как рекурсия `applyTheme` → `Store.set`).
Их закрывают тесты — см. `tests/`.

## Чего в проекте нет и почему

Git-репозитория нет. Перед крупной миграцией стоит сделать `git init` и первый коммит —
иначе массовые переименования нельзя откатить.
